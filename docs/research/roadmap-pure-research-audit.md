# 路线图纯研究任务审计

本文审计 [`docs/roadmap.md`](../roadmap.md) 的全部开放事项，区分“可以只靠数学推导、独立高精度/形式化/数值 witness、规范决策或 test-only evidence 在当前分支复算闭合的研究前置”与“必须由 production 实现、真实 GPU/双平台硬件或性能测量闭合的工程工作”。本文是研究记录，不定义产品行为、科学支持域、public API、fixture/schema 版本或完成状态；这些事实仍分别以[产品合同](../product.md)、[数学物理](../physics.md)、[验证合同](../validation.md)、[架构](../architecture.md)、[平台](../platform.md)、[渲染准入](../rendering.md)、[Reference 证据](../reference-implementation.md)、[GPU 证据](../gpu-renderer.md)与[路线图](../roadmap.md)为准。

**审计结论：本审计预注册、且不依赖新 consumer 或 production/GPU seam 的 active 纯研究切片已经全部闭合。** 相邻 surface/capture、critical/higher-order pair（[证书](critical-curve-surface-capture.md)）、具名 negative-spin continuous case（[证书](negative-spin-continuous-witness.md)）、near-axis/near-extreme conservative fallback（[证书](near-axis-extreme-fallback.md)）以及 KA-1/2 Carlson + root-topology CPU oracle（[证书](carlson-kerr-oracle.md)）均已有可复算证据。它们只关闭“独立 witness/支持域判定”这一层；路线图剩余项是 `M/E/X`，或须先出现真实 consumer/新产品合同才会激活的条件性研究，不能由本分支单独关闭 GPU、quality policy、artifact、reconstruction、平台或发行事项。

## 1. 判定规则与共同闭合门槛

| 标记 | 含义 | 能否据此把路线图事项标为完成 |
| --- | --- | --- |
| `R` | 纯研究交付本身可在当前分支复算闭合；产物限于研究脚本、证明/证书、研究记录或 test-only consumer | 只能关闭明确写成“independent witness/CPU oracle/分类证书”的子项 |
| `M` | 混合事项；存在 `R` 型前置，但路线图原项还要求 production/GPU/consumer/hardware | 不能；必须分别记录研究层与工程层状态 |
| `E` | 结论依赖真实 production seam、设备执行、双平台/生命周期/性能或发行资产 | 不能用离线研究替代 |
| `X` | 路线图已明确否决、排除或要求出现新消费者后再打开 | 不能作为“尚待调参”的纯研究 backlog |

所有新高精度 continuous-field case 共用以下预注册规则，避免每个 stratum 自定义更宽松的证据：

1. **`HP` 独立证书。** 从 canonical decimal input 独立重建 observer tetrad/covector，不读取 Rust/GPU trace；在 BL/Mino separated equations 中保存 root topology、initial signs、turning/crossing count、signed winding、terminal/event order、source/escape、frequency ratio、coordinate-time duration、radiance及 event/invariant diagnostics。Carter 的 Hamilton–Jacobi separability 给出第四常数与 quadrature（[Carter 1968](https://doi.org/10.1103/PhysRev.174.1559)）；pure Kerr exterior 的 manifestly real root classification/elliptic solution只覆盖其声明域，不能据此外推到任意退化拓扑（[Gralla–Lupsasca 2020](https://doi.org/10.1103/PhysRevD.101.044032)）。
2. **`HP-precision` 可复算性。** 用锁定的 [`mpmath` 研究环境](python-research-tooling.md)在 120/180 decimal digits 下完整重建，不复用低精度 roots；每个 semantic scalar/vector lane 的 maximum normalized delta `<1e-80`，约束/primitive residual `<10^(15-p)`（`p` 为 working precision），且 signed classification/event-order margin 大于独立误差界与相应 consumer gate 的保守和。`mpmath` 支持任意精度，但 `polyroots` 可能需要额外精度且 repeated roots 会恶化收敛，端点/奇异积分也需要显式处理；因此“提高 `mp.dps`”本身不是误差证明（[`mpmath` 1.3.0 官方文档](https://mpmath.org/doc/1.3.0/)）。
3. **`Semantic` 验收。** terminal/branch/topology/count exact；连续字段逐 channel 使用[验证合同 §5.2](../validation.md#52-reference-agreement)的现有预算，不得用 RGB max error、potential residual 或 CPU/GPU agreement替代。Accepted case 必须 zero false acceptance；margin 不足则输出 typed unsupported/fallback，而不是放宽 gate。
4. **`RED` 证伪能力。** 每个新 stratum 先有 deterministic test，至少故意翻转 physical-spin sign、root/turning branch、event order 或 source-phase wrapping 中一项，并证明证书/consumer 会失败；测试观察语义，不冻结 helper、quadrature 分段或打印格式。当前九点的既有 RED/GREEN 与 120/180 证书见[continuous-field corpus §6](continuous-field-corpus.md#6-九点-semantic-fields-的采用与恢复条件)。
5. **研究边界。** `HP` 证书不自动成为 versioned fixture/artifact；只有真实 Instrument consumer 落地时才引入 schema identity/version。[路线图明确要求 schema 与首个 consumer 一并落地](../roadmap.md#连续字段证据与质量政策)，而当前 `SampleRetrace` ticket 只是 process-local request identity（[`inspection.rs`](../../crates/gravlume-render/src/trace/inspection.rs)）。

## 3. 真实 consumer 之前的 reconstruction / reuse

## 4. Kerr 专用解析/半解析 accelerator

[路线图](../roadmap.md#kerr-专用解析加速)给出的顺序是 high-precision/CPU oracle → root classifier → terminal solver → GPU bake-off；Cartesian Kerr–Schild 始终定义 unsupported/uncertain domain。现有 production 仍是固定 `gpu-ks-rk4-v2` 的 Cartesian Kerr–Schild WGSL path（[`geodesic_integration.wgsl`](../../crates/gravlume-render/src/shaders/geodesic_integration.wgsl)）。Fixed-step reciprocal-Mino 曾出现 `2.661354e-3 M` 的 terminal travel-time error，超过 `1e-3 M` gate，已被否决；恢复需要 phase-error certificate，不是经验缩小步长（[Mino step 研究](mino-step-selection.md)）。

### 4.1 Carlson / binary32 / host-WGSL 边界

- WGSL host-shareable `f32/u32` alignment/size 为 `4/4`，`vec3` 是 `16/12`，`vec4` 是 `16/16`（[WGSL alignment and size](https://www.w3.org/TR/WGSL/#alignment-and-size)）。Rust `#[repr(C)]` 定义字段顺序/offset算法，`align` modifier本身不替代 C representation；因此任何未来 accelerator DTO仍须显式 `#[repr(C)]`、只含 scalar/array lane，并有 size/alignment/offset assertions（[Rust Reference: type layout](https://doc.rust-lang.org/reference/type-layout.html#the-c-representation)）。这是一条 ABI约束，不是 SIMD宽度保证。
- WGSL `f32` 使用 binary32表示，但规范不固定 rounding mode，允许规定范围内的 flush-to-zero、reassociation与 fusion（[floating-point differences](https://www.w3.org/TR/WGSL/#floating-point-differences)、[reassociation/fusion](https://www.w3.org/TR/WGSL/#reassociation-and-fusion)）。`KA-1/2` 已把高精度域收窄到 separated Ib 与 positive-real Carlson，但这仍不是逐操作 binary32 condition interval；高精度稳定不能直接外推 WGSL稳定。
- Runtime storage-array长度由 effective binding size决定（[WGSL runtime arrays](https://www.w3.org/TR/WGSL/#buffer-binding-determines-runtime-sized-array-element-count)）；当前 test corpus的独占-index、越界返回、`8×8×1` dispatch可继续用于未来 GPU comparison。若 accelerator引入跨 workgroup producer/consumer，必须分 dispatch/pass；Workgroup-scope barrier不足以建立该可见性（[WGSL memory semantics](https://www.w3.org/TR/WGSL/#memory-semantics)）。
- 资源 admission只能使用实际 requested device limits；`wgpu::Device::limits()` 返回创建 device时请求的 limits，不能假定 adapter未请求的更高能力（[`wgpu 30 Device::limits`](https://docs.rs/wgpu/30.0.1/wgpu/struct.Device.html#method.limits)、[WebGPU limits](https://www.w3.org/TR/webgpu/#limits)）。离线 Python不能关闭 layout validation、shader validation、dispatch/resource或 backend差异。

## 7. 建议执行顺序与停止线

纯研究 backlog 建议按下列顺序执行：

1. `P0 negative-spin continuous witness`：**研究层已完成**；private BL/Mino seam 已锁住 signed spin/chart/emitter branch 与 continuous fields。
2. `P1 surface/capture competing-event pair`：**研究层已完成**；新的 terminal boundary 保持在 topology-local private builder。
3. `P2 critical/higher-order`：**研究层已完成**；已保存多 turning segment、unwrapped phase、winding 与 distance-to-critical 证书。
4. `P3 near-axis/near-extreme fallback certificate`：**研究层已完成**；只认证 conservative support boundary，病态 case 全部 fallback，regular control 不冒充 supported。
5. `KA-1/2 Carlson + topology CPU oracle`：**纯研究层已完成**；exact-isolated I--IV classifier、
   positive-real Carlson definitions/identities 与 actual Ib radial reduction 均已锁定，仍只是旁路
   accelerator oracle，不得阻塞 surface 产品闭环或绕过 observable ladder。

至此没有仍处于 active、且能只靠当前仓库离线证据闭合的预注册 `R` 项。后续工作都需要
production Rust/WGSL、真实 consumer、持久 artifact、目标硬件或 correctness-approved benchmark；
若未来产品合同激活新的 `X→R` 子课题，应重新预注册问题、定义域和停止线，而不是把它并入本次完成声明。

每个任务到 `HP` 证书、mutation RED与研究记录即停止。以下行为都越过纯研究边界，必须作为后续工程任务单独授权和验收：修改 production Rust/WGSL solver、增加 public API/trait、分配持久 schema version、实现第二 quality method、声称 GPU/`RGBA16F` 支持、运行双平台发布矩阵、采集性能或加入真实 asset/history consumer。
